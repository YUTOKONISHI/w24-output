# 一覧のページ送り

一覧画面が全件を取得している状態を、`paginate()` に置き換える計画である。
`20260801-settings-stock-management-screens.md` の「対象外／別タスクとして起票する」に挙げた「通知履歴のページネーション」を引き取り、対象を広げた。

## 対象

`->get()` で全件を返している一覧は5つある。
このうち3つをページ送りにする。

| 一覧 | 扱い |
|---|---|
| 通知履歴（`/app/notifications`） | 対象 |
| ストック一覧（`/app/stocks`） | 対象 |
| 管理の商品一覧（`/admin/dashboard`） | 対象 |
| 管理のカテゴリ（サイドバーとダイアログ） | 対象外 |
| ダッシュボードの購入予定品（`/app/dashboard`） | 対象外 |

通知履歴は利用者ごとに1日1行増えるので、放っておくと最初に効いてくる。

### カテゴリをページ送りしない理由

カテゴリの配列は、絞り込みのサイドバーとカテゴリ管理ダイアログの両方に渡っている。
サイドバーは絞り込みの選択肢そのものなので、2ページ目に送られたカテゴリはチェックできなくなる。
絞り込みの候補が画面から消える状態は、件数の削減で得られるものに見合わない。

カテゴリは商品マスタの分類であり、商品と違って管理者が日々増やすものでもない。

### ダッシュボードをページ送りしない理由

この画面は次に買うものを見せる場所で、要件も「購入予定品を表示」「ストック数を1のものを優先表示」としか言っていない。
ページ送りを付けると、優先表示で先頭に集めた意味が薄れる。
件数を絞るなら上位いくつかに限る形になるが、それは要件の読み替えになるため触らない。

## 決めたこと

### 1ページの件数は画面で変える

一般ユーザーの2画面は20件、管理の商品一覧は50件とする。
前者はスマートフォンで1件が縦に長く、20件でも数回のスクロールになる。
後者は表形式で1件が1行に収まり、レスポンシブ対応の対象外でもある。

### 管理画面の絞り込みをサーバ側に移す

現在の絞り込み（`useCategoryFilter`）は、全件を受け取ってからクライアントで `filter` している。
ページ送りを入れると、絞り込みの対象が今のページの中だけになり、2ページ目にある該当商品が消える。

チェックしたカテゴリをクエリ文字列で送り、`whereIn('category_id', ...)` で絞る形に改める。
`useCategoryFilter` は選択状態の保持とサーバへの再取得だけを担い、`filteredProducts` を返さなくなる。

再取得は Inertia の `router.get` に `{ preserveState: true, preserveScroll: true, replace: true }` を付けて行う。
チェックのたびに履歴が積まれると、戻るボタンで絞り込みを1つずつ剥がすことになる。

ページ送りのリンクには `withQueryString()` が要る。
付けないと、2ページ目に移った時点で絞り込みが外れる。

### ページャは番号を自分で組む

`paginate()` が返す `links` 配列はそのまま使わない。
`&laquo; Previous` のようなHTMLの実体参照がラベルに入っており、日本語にするには結局作り直すことになる。

`current_page` と `last_page` から番号を組み、前後の矢印と「N件中 x件目からy件目」を添える。
共通の部品として `shared/components/Pagination.tsx` に置き、3画面から使う。

### 空になったページはそのまま表示する

通知履歴の削除は `back()` で今のURLに戻るため、ページ番号は保たれる。
2ページ目の最後の1件を消すと、`data` が空の2ページ目が表示される。

ページ番号を繰り上げる処理は入れない。
ページャの番号は残るので、1ページ目に戻る手段は画面にある。

## 変更するもの

### サーバ

| ファイル | 変更 |
|---|---|
| `NotificationLogController::index` | `paginate(20)` |
| `StockController::index` | `paginate(20)` |
| `Admin/ProductController::index` | `categories` を受けて絞り、`paginate(50)->withQueryString()` |

### フロント

| ファイル | 変更 |
|---|---|
| `shared/types/pagination.ts` | 新規。`Paginated<T>` |
| `shared/components/Pagination.tsx` | 新規 |
| `pages/notifications.tsx` | `notifications` の型を `Paginated<NotificationLog>` に |
| `pages/stocks/index.tsx` | 同上 |
| `pages/admin/dashboard.tsx` | 同上。絞り込みの受け渡しが変わる |
| `features/admin/hooks/useCategoryFilter.ts` | サーバへの再取得に変更 |

`Paginated<T>` は `data` と、`current_page` / `last_page` / `per_page` / `total` / `from` / `to` を持つ。
`links` は使わないが、`paginate()` の応答には含まれる。

## 検証

`composer ci:check` に加えて、画面で次を確認する。

- 通知履歴を21件以上にしてページャが出ること。2ページ目で履歴を消したあとも2ページ目に留まること
- ストック一覧のページャ
- 管理の商品一覧で、カテゴリのチェックを外すと件数が変わり、2ページ目に移っても絞り込みが残ること
- 絞り込みを操作したあとブラウザの戻るボタンで管理画面から出られること

シーダーが入れる通知履歴は数件しかないので、確認には `NotificationLogSeeder` の件数を増やすか、`tinker` で行を作る。

## 対象外

- **無限スクロール**。Inertia の `merge` を使う形。番号付きのページャで足りている
- **並び替えと検索**。要件に無い
