# GitHub Actions が落ちている件の修正

## 手順

1. 本ドキュメントを `doc/plans/20260816-ci-fixes.md` として保存する。
2. 追記式とし、方針が変わった場合は末尾に `## 改訂（YYYY-MM-DD）` を足す。既存の記述は書き換えない。

## Context

`.github/workflows` に `linter` と `tests` の2つがある。`tests` が3か所で落ちており、`linter` は通るものの検査として働いていなかった。

`gh` が入っておらずリポジトリも private のため、実行ログを直接は読めない。各ステップをコンテナ上で再現して原因を特定した。

| ワークフロー | ステップ | 状態 |
|---|---|---|
| tests | `composer install`（PHP 8.3 のジョブ） | 失敗 |
| tests | `composer types:check` | 失敗（33件） |
| tests | `php artisan test` | 失敗（1件） |
| linter | `npm run format` / `npm run lint` | 通るが検査になっていない |

## 1. PHP 8.3 のジョブが `composer install` で落ちる

マトリクスが `['8.3', '8.4', '8.5']` で、`composer.json` も `"php": "^8.3"` を宣言していた。ところが `composer.lock` の symfony 各パッケージが `php >=8.4.1` を要求している。

```
symfony/console v8.1.1 requires php >=8.4.1
  -> your php version (8.3.33) does not satisfy that requirement.
```

宣言が実態に追いついていない。`laravel/framework` v13 が symfony 8.1 を引き込み、そちらが 8.4.1 以上を要求している。

`composer.json` の `require.php` を `^8.4` にし、マトリクスから 8.3 を外した。宣言を実態に合わせるのが筋であって、マトリクスだけ削ると `composer.json` は 8.3 で動くと言い続けることになる。

`composer update --lock` で lock の `content-hash` と `platform` を更新した。パッケージのバージョンは動かない。差分は2行である。

## 2. phpstan の33件

すべて既存コードの型注釈の不足で、今回の変更で増えたものではない。level 7 を通していないので、`tests` はこれまで一度も緑になっていない。

| 種類 | 件数 | 内容 |
|---|---|---|
| `missingType.return` | 23 | コントローラのメソッドに戻り値型が無い |
| `missingType.generics` | 8 | モデルのリレーションがジェネリクスを指定していない |
| `class.notFound` | 2 | `Admin` の PHPDoc が `Carbon` を参照しているが import が無い |

baseline で黙らせる案もあったが、注釈を書いて直すことにした。既存の33件を残したままだと level 7 が実質的に守られない。

### コントローラの戻り値型

`Inertia::render()` を返すものは `Inertia\Response`、`back()` と `to_route()` と `redirect()` を返すものは `Illuminate\Http\RedirectResponse` になる。`Admin\AuthController::login` は成功時に `redirect()->intended()`、失敗時に `back()->withErrors()` を返すが、どちらも `RedirectResponse` なので分岐は要らない。

### リレーションのジェネリクス

Larastan は `HasMany` と `BelongsTo` に2つの型引数を求める。関連先のモデルと、宣言しているモデル自身である。

```php
/** @return BelongsTo<Category, $this> */
public function category(): BelongsTo
```

戻り値の型宣言（`: BelongsTo`）はそのままにして PHPDoc で補う。型宣言側にジェネリクスは書けない。

### `Admin` の Carbon

`app/Models/Admin.php` の PHPDoc が `Carbon|null` と書いているのに `use Carbon\Carbon;` が無く、`App\Models\Carbon` として解決されていた。他のモデルは import 済みで、`Admin` だけ漏れていた。

## 3. `ExampleTest` が `route('home')` を呼ぶ

Laravel の雛形のまま残っていた。`routes/web.php` に `home` という名前のルートは無く、`/` は `/app/welcome` へのリダイレクトである。

雛形の意図はアプリが起動して画面を返すことの確認なので、`route('welcome')` に差し替えた。`welcome` は認証不要で、`Route::inertia` が 200 を返す。

`tests/Unit/ExampleTest.php`（`true is true`）は雛形のままだが通るので触っていない。

## 4. `linter` が検査になっていなかった

```yaml
- name: Format Frontend
  run: npm run format      # prettier --write
- name: Lint Frontend
  run: npm run lint        # eslint . --fix
```

どちらも書き込みモードである。`prettier --write` は常に成功するため、整形の崩れを検出できない。直した結果をコミットする `stefanzweifel/git-auto-commit-action` のステップはコメントアウトされているので、CI が直した内容はそのまま捨てられていた。

`package.json` には `format:check` と `lint:check` が既にある。PHP 側も `composer lint`（pint 実行）ではなく `composer lint:check`（`--test`）に変えた。

あわせて次を直した。

- `actions/setup-node` が無く、ランナー既定の Node 版に依存していた。`tests` と同じ 22 に固定する
- `npm install` を `npm ci` にする。lock を尊重し、CI での再現性が上がる
- `permissions: contents: write` を `read` にする。書き込みが要るのはコメントアウトされた自動コミットだけで、`persist-credentials: false` とも食い違っていた
- トリガーのブランチから `develop`、`master`、`workos` を外す。このリポジトリに存在しない

`tests` 側には `npm run types:check`（`tsc --noEmit`）を足した。フロントの型検査がどのワークフローにも入っていなかった。

## 5. prettier の設定とコードの食い違い

`format:check` に切り替えると44ファイルが落ちる状態だった。`.prettierrc` が `tabWidth: 4` / `printWidth: 80` を指定しているのに対し、手書きのコードは2スペース・100桁前後で書かれている。

設定をコードに合わせることにした。逆向き（コードを4スペース・80桁に再整形）だと差分がはるかに大きくなり、直後の `git blame` が読めなくなる。

`tabWidth: 2` / `printWidth: 100` にしたうえで、残る差分を `prettier --write` で解消した。26ファイル、180行の追加と194行の削除になる。内訳は雛形由来のファイル（`app.tsx`、`shared/lib/utils.ts`、`shared/types/*`）の4スペースから2スペースへの変更と、100桁に収まる行の連結である。

### `.prettierignore` を直した

`resources/js/components/ui/*` を指したままだった。`20260816-frontend-structure-refactor` の移動で `resources/js/shared/components/ui/*` になっている。私の見落としである。

あわせて Wayfinder の生成物（`actions`、`routes`、`wayfinder`）も除外した。`npm run format` は `resources/` 全体を対象にしており、ビルドのたびに作り直されるファイルを整形しても差分が揺れるだけである。ESLint 側は既に除外していた。

`resources/css/app.css` も整形の対象に入っており、1ファイル分の差分が出る。
